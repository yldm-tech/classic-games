# 安全与合规

国内 UGC + 游戏 + AI 生成内容,合规是**硬约束,不是可选项**。
安全和合规在架构里当一等需求,不做事后补丁。

> 说明:本文针对的是在线服务(账号与实名、用户发布内容与审核、社交、AI 生成、充值与支付等 API)。在线服务已实现并有测试,属于可选组件;当前的主机风格启动器完全在本地运行,没有接入它,启动器里没有账号、用户发布内容、AI 生成和支付功能。产品定位见 [01-vision](./01-vision.md),决策见 [ADR-016](./decisions.md)。

## 一、内容合规(最重)

### 双重内容审核

UGC 平台必备,且本平台有 AI 生成 + 用户 Fork 两个内容来源,都要审:

- **AI 生成内容**:AI 起的游戏名、简介等文字进审核;DSL 本身是结构化枚举,风险低,但引用的素材/文字要管。
- **用户发布**:Fork 后发布的作品(标题/简介/封面/标签)进审核队列(`moderation_jobs`,见 [10-data-model](./10-data-model.md))。
- **用户互动**:评论、私信、昵称/简介,走文本审核(敏感词 + 模型)。
- 流程:AI/规则预审 → 命中风险转人工 → 裁决。发布态 `reviewing → published/rejected`([10](./10-data-model.md))。

### 举报与处置

- 游戏/评论/用户三类举报入口([09-api-design](./09-api-design.md) `moderation`)。
- 屏蔽、不感兴趣、下架链路。

## 二、监管合规

### 版号 —— 商业可行性前置门,不是「上线前法务项」

**这是唯一可能让整个产品在国内不成立的关卡,且与技术成熟度无关:做得再好,拿不到版号也不能合法运营。** 必须在 Phase 0 之前就有结论,否则技术 spike 成功反而沉没更多成本。要前置调研清楚:

- **主体资质**:游戏运营需版号 + ICP + 网络文化经营许可;个人/小团队近乎拿不到版号(发放长期收紧)。
- **UGC 的版号归属难题**:平台是一个 Runtime + 海量用户 Fork——**每个 Fork 算不算「新游戏」、需不需要各自版号?** 这是 AI 生成 + UGC 双重敏感点,无先例可直接套,必须法务专项确认。
- **拿不到时的备选路径**(决定整个商业形态,需尽早选):出海优先 / 走小游戏渠道(微信小游戏等另一套合规) / 找有资质的合规主体合作 / 改非「游戏」定性。这条选什么,直接影响市场定位与商业模式。

工程侧配合:未过审内容不可公开。

- **实名认证**:`realname_status`,关键操作(发布、充值、社交)按要求校验。
- **青少年模式**(国内强制):
  - 独立密码进入/退出。
  - 时长限制(如每日 40 分钟)、宵禁时段。
  - 内容过滤(只见适龄内容)。
  - 消费限制。
  - 原型已有该模块,方向对,工程化落地。
- **未成年人保护**:疑似未成年走更严策略。

## 三、数据安全

- **密钥管理**:模型 API key、S3 凭证、DB 密码**只在后端**,走密钥管理服务/环境变量,绝不进客户端或仓库([08-deployment](./08-deployment.md))。
- **传输**:全链路 HTTPS。
- **认证**:token 有期 + refresh;短信验证码限频防爆破。
- **个人信息**:手机号等 PII 加密存储、最小化收集、可注销账号(原型有注销二次确认)。
- **备份**:DB 定期快照 + 异地;S3 版本化。

## 四、生成式 AI 监管(独立于版号的另一条硬监管线)

国内对「AI 生成内容」有一套**独立**的强制监管,与版号是两条不同的线,**漏一条即不合规**:

- **算法备案**:《生成式人工智能服务管理暂行办法》要求提供生成式 AI 服务做算法备案 / 大模型备案。Classic Games 用 AI 帮用户生成游戏内容,落在监管范围内。
- **生成内容显著标识**:深度合成 / AI 生成内容需按规定**显著标识**(告知用户「此内容由 AI 生成/辅助」)。AI 起的游戏名、AI 生成的作品都涉及。
- **训练数据 / 模型合规**:若用境外模型(Claude/GPT/Gemini),数据出境与模型可用性本身有合规约束,与 [ADR-008](./decisions.md) 的模型选型挂钩。
- 这条也影响成本:每次创作的内容审核是随创作量线性增长的成本线,与 AI 调用成本并列。

## 五、AI 安全

- **输出只进 DSL 校验,绝不 eval / 执行代码**([12-ai-prompt](./12-ai-prompt.md))。这是 AI「不生成可执行代码」原则的安全意义所在。
- **Prompt 注入防护**:用户输入当数据不当指令;系统提示不可被覆盖;只接受 schema 内 JSON Patch,其余丢弃。
- **生成内容审核**:AI 产出的文字进内容审核管线(见上)。

## 六、滥用与成本防护

- **AI 接口限流 + 配额**:免费额度 + 充值/看广告补充;按用户/IP 限频。防刷防爆成本([08](./08-deployment.md) / [12](./12-ai-prompt.md))。
- **发布/Fork 频率限制**:防批量灌垃圾内容。
- **风控**:异常账号(批量注册、机器行为)识别。

## 七、支付合规

- 移动端内购走 App Store / Google Play / 国内渠道规则。
- 创作点充值、创作者提现涉及资金,需合规通道与对账;写操作幂等(`Idempotency-Key`,见 [09](./09-api-design.md))。

## 落地优先级(对应 roadmap)

| 项 | 何时必须就位 |
|---|---|
| **版号可行性 + 生成式 AI 备案调研** | **Phase 0 之前(立项前置门,法务专项)** |
| 数据安全(密钥/HTTPS/认证) | Phase 0/1,从一开始 |
| 实名 + 基础内容审核 | Phase 1(有发布就要审) |
| AI 安全边界(无 eval/注入防护) | Phase 1,随 AI 接口 |
| 生成内容显著标识 | Phase 1(有 AI 生成内容就要标) |
| AI 限流配额 | Phase 1,随 AI 接口(控成本) |
| 青少年模式完整 | Phase 2 |
| 支付合规 | 引入付费时(Phase 2/3) |

合规相关风险在 [06-challenges](./06-challenges.md) §I 也有登记;两处保持一致。
