# 国际化(i18n)

默认简体中文,支持 中文 / English / 日本語。
原型在多语言上投入很重(界面文案、游戏名、简介、数字格式、渠道、品牌图标全随语言切换),这套要在 Godot 客户端落地并保持。

## 范围:不止翻译文案

多语言要覆盖的不只是 UI 字符串:

| 维度 | 例子 | 注意 |
|---|---|---|
| UI 文案 | 按钮、标题、提示 | 标准翻译 |
| 内容文案 | 游戏名、简介、动态通知 | 官方内容三语;用户内容不强制翻译 |
| 数字格式 | 4.8万 vs 48.2k | 中文用「万/亿」,英日用 k/M |
| 渠道本地化 | 登录/分享/支付的第三方 | 见下表 |
| 品牌图标 | 微信/Apple/LINE… | 随语言切换对应渠道图标 |
| 文案术语 | Fork→二创 / remix / リミックス | 见 [glossary](./glossary.md) |
| `<html lang>` / 标题 | — | 随语言动态切换(Web) |

## 渠道按语言本地化

原型确定的对应关系,客户端平台插件层([16-client-architecture](./16-client-architecture.md))按 locale 切换:

| 场景 | 中文 | English | 日本語 |
|---|---|---|---|
| 登录第三方 | 微信 / QQ / Apple | Apple / Google / Discord | LINE / Apple / Google |
| 分享 | 微信 / 朋友圈 / QQ / 复制链接 | Messages / X / Discord | LINE / X / Discord |
| 支付 | 微信支付 / 支付宝 / Apple Pay | Apple Pay / 银行卡 / PayPal | Apple Pay / クレジット / PayPay |

## Godot 实现

- **字符串表**:Godot 内置翻译(CSV / gettext PO + `tr()`)。维护中/英/日三列。
- **运行时切换**:语言是全局状态([16](./16-client-architecture.md) 的 state),切换即时重渲;设置页「语言」是真开关(原型曾把它做成死的,踩过坑)。
- **数字格式化**:封装一个 `format_number(n, locale)` 工具:中文走「万/亿」,英日走 k/M。原型已实现这套(4.8万 ↔ 48.2k),逻辑搬过来。
- **CJK 字体**:中日文显示用 HarfBuzz,Godot 渲染没问题([06-challenges](./06-challenges.md) §C);需打包覆盖中日文的字体(如 Noto Sans CJK),注意包体。
- **图标**:品牌 glyph 按 locale 选用对应 SVG(单色,跟随主题色)。

## 文案质量要求

原型迭代里有一条硬教训:**机翻腔不可接受**。

- 不直译程序员黑话:`fork → 二创`(不是「分叉」)、`forge → 创作/生成`(不是「锻造」)、`explore → 发现`。术语对照见 [glossary](./glossary.md)。
- 三语都要由懂当地语境的人过一遍,日语尤其注意自然措辞(原型修过多处生硬日语:フォーク→リミックス、鍛造→つくる)。
- 中文数字写法:`2100` 不写 `2,100`(中文不用千分位逗号)。

## 排版细节(原型踩过的坑)

- **中文数字/徽章换行**:大数字(如「8.6万」)、徽章文字要防止在词中间换行——用 `nowrap` + 不间断空格 ` `,分数/数字永远单行。Godot 里对应控制 `Label` 的 autowrap 与文本组装。
- 这类问题在原型里反复出现,客户端实现时把「数字/短徽章不换行」作为组件默认行为。

## 与 AI 层的关系

- AI 生成的文字(游戏名、提示)按当前 locale 生成,并进内容审核([14-security-compliance](./14-security-compliance.md))。
- 未命中素材的提示文案(「资源库暂无 X,已用 Y 代替」)也要三语([12-ai-prompt](./12-ai-prompt.md))。

## 落地节奏

- Phase 1:框架先就位(字符串表 + 运行时切换 + 数字格式化),默认中文,英日可先机翻占位但**核心路径**(登录/创作/发布)三语要顺。
- Phase 2:全量三语精校,渠道/图标本地化补齐。
