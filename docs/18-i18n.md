# 国际化(i18n)

客户端(主机风格启动器,见 [16-client-architecture](./16-client-architecture.md))默认简体中文,另提供 English。语言是设置里的一项,切换后立即生效。

## 范围

| 维度 | 放在哪里 | 说明 |
|---|---|---|
| 界面文案 | `apps/client/i18n/launcher_strings.gd` | 按钮、标题、提示、设置项说明等,每个 key 以 `launcher.` 开头,后接所属屏幕或区域(`launcher.nav.home`、`launcher.settings.*`) |
| 游戏内容 | 每款游戏的清单 `apps/client/games/<id>/game.json` | 游戏名、类型、一句话介绍、成就的名称与说明、玩法说明、操作名、HUD 标签、开局选项是游戏自己的数据而不是文案:每个字段是 `{ "zh": …, "en": … }`,由 `LauncherCatalog.text` / `LauncherGameGuide.text` 读取。清单校验要求两种语言都填 |
| 数字与时间 | `apps/client/launcher/launcher_format.gd` | 分数加千分位(`128,450`)、游玩时长(`3h 12m`)、局内计时(`MM:SS`)、「今天 / 昨天 / N 天前」 |
| 时钟 | `LauncherSettings.clock_text` | 24 / 12 小时制是独立的设置项 `clock_24h`,上午 / 下午的写法随语言 |

运行时(`apps/client/runtime/`)不含面向玩家的文案,也不依赖 `i18n/`。游戏模块同样不依赖 `i18n/`:它在局内自己画的文字按开局时收到的 `locale` 选择,文本放在自己的目录里。

## 机制

- **入口**:`Strings.t(locale, key)` 取文案,`Strings.fmt(locale, key, args)` 填充 `%s` / `%d` 格式串(`apps/client/i18n/strings.gd`)。`Strings.LOCALES` 是可选语言(`zh`、`en`),`Strings.DEFAULT_LOCALE` 是 `zh`。屏幕不直接调用它们,而是用外壳的 `LauncherRoot.t` / `fmt`,由外壳带上当前语言。
- **回落**:某个语言缺少的 key 回落到中文;中文也没有时原样返回 key 并打印警告,开发时一眼可见。目录字段同样回落到 `zh`。
- **切换**:`LauncherRoot.set_locale` 把语言写进存档的 `lang` 设置项,销毁并重建所有屏幕和顶部导航,当前屏幕保持不变;PC 模式在下次显示时按新语言重建。启动时从存档读取,存档里不是可选语言的值按默认语言处理。
- **格式串**:带参数的 key 以 `_fmt` 结尾。两种语言里同一个 key 的占位符个数必须一致。
- **字体**:仓库不带字体文件,`LauncherTokens.font` 在运行时从系统字体里按顺序选第一个已安装的家族(中文 Noto Sans SC / 思源黑体 / 苹方 / 微软雅黑,拉丁 Inter / SF Pro / Helvetica Neue / Segoe UI)。系统中文字体没有 800 / 900 字重时用合成加粗补足。

## 测试守住的约束

`make launcher-test` 里的文案测试要求:中文与英文定义完全相同的一组 key;每个 key 都带 `launcher.` 前缀;同一个 key 的占位符个数在两种语言里一致;`Strings.LOCALES` 恰好是文案表里有翻译的语言。目录测试要求每款游戏和每个成就的名称、说明两种语言都不为空。

## 增加一种语言

1. 在 `launcher_strings.gd` 的 `TABLE` 里加入该语言的完整一份,不留只有部分 key 的表。
2. 给每款游戏清单(`apps/client/games/*/game.json`)的每个本地化字段补上该语言,并让 `games/shared/game_manifest.gd` 的校验要求它。
3. 把语言代码加入 `Strings.LOCALES` 和 `LauncherSettings` 里 `lang` 的可选值,并给设置屏的语言选项补上显示名。
4. 确认 `LauncherTokens` 的字体家族列表覆盖该语言的字形,否则补上对应的系统字体。
5. 用 `make launcher-shot` 逐屏查看([19-design-system](./19-design-system.md)):译文更长时标题、按钮和页脚提示不能溢出或换行。

## 文案质量要求

- 不直译程序员黑话,术语对照见 [glossary](./glossary.md)。
- 每种语言都要由懂当地语境的人过一遍,机翻腔不可接受。
- 中文界面里的英文装饰字(品牌的拉丁写法、`FAVORITE` 这类标签)是设计的一部分,保持英文。
- 数字、分数、短标签永远单行显示;`Label` 默认不自动换行,需要换行的正文才显式打开。
