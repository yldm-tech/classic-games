# 蓝图与愿景

## 一句话

Classic Games(经典厅)是一个开源的主机风格游戏启动器,自带一组经典类型的原创游戏,用手柄或键盘游玩,另有面向键盘鼠标的 PC 模式。

## 定位

- **是什么**:一个打开就能玩的游戏合集。启动器负责选游戏、看记录、看成就、改设置;每款游戏都是经典类型里的一款原创作品。
- **怎么操作**:手柄或键盘可以完成全部操作;PC 模式是同一份数据的另一种布局,面向键盘和鼠标,按 F11 或长按手柄 View 键切换。
- **数据在哪**:全部进度保存在本机的一个存档文件里。启动器不登录、不发网络请求。
- **不是什么**:不是 UGC 社区,不是 AI 创作工具,也不是模拟器或经典游戏的复刻合集。启动器里没有信息流、发布、评论、账号和付费。

项目处于预发布阶段:没有公开的构建,只能从源码运行。

## 三层结构

### 启动器

`apps/client/launcher`,客户端的主场景。固定 1920×1080 画布,随窗口整体缩放。包含首页、游戏库、成就、设置(含键盘改键与存档导入导出)、单款游戏的菜单、局内 HUD、暂停与结算,以及 PC 模式。界面上关于玩家的一切(游玩时长、最高分、收藏、成就)都读自本地存档,没有记录时如实显示空状态。详见 [16-client-architecture](./16-client-architecture.md) 第 8 节。

### 游戏

每款游戏是 `apps/client/runtime` 下的一个数据驱动的 Runtime,玩什么由一份 Mod DSL 文档描述。启动器运行每个 Runtime 自带的基线文档(`baseline.dsl.json`),只经 `runtime/game_session.gd` 这一个边界与游戏交换数据。Mod DSL 的设计见 [05-dsl-design](./05-dsl-design.md),各 Runtime 的内容见 [11-runtime-content](./11-runtime-content.md)。

目前有三款游戏:

| 游戏 | Runtime | 类型 | 一句话 |
|---|---|---|---|
| 星环巡航 / Orbit Patrol | `shooter` | 飞行射击 | 清空这片星域,再击落守在尽头的机甲。 |
| 长夜草原 / Meadow Vigil | `survivor` | 生存动作 | 只管走位,武器自己开火。撑过三分钟。 |
| 隘口守卫 / Gatewatch | `tower_defense` | 塔防 | 沿路布下箭塔与炮台,别让一个敌人走到终点。 |

三款都是单人游戏。局内画面目前是几何图形,没有贴图美术;启动器里的主视觉是插画,不代表实际画面。

### 可选的在线服务

Go 后端(`apps/server`)、命令行(`apps/cli`)、MCP 服务(`apps/mcp`)和 Go SDK(`packages/sdk`)实现了 Mod DSL(schema 校验、RFC 6902 补丁、迁移,以及与 GDScript 实现共用 golden 文件的一致性测试)和一套在线服务的 API(账号、游戏目录、Mod、社区、商业化)。它们可以运行、有测试,但属于可选组件:启动器没有接入其中任何一个,不运行它们也能玩全部游戏。架构见 [04-architecture](./04-architecture.md),接口见 [09-api-design](./09-api-design.md)。

## 内容原则:原创

合集里的每款游戏都必须是原创作品。可以做经典的类型,不可以复刻某一款现有的商业游戏:

- 名称、角色、美术、音乐和关卡都为本项目制作,不照搬、不描摹、不改名沿用现有商业游戏的内容,也不使用其商标。
- 每一份素材都要有来源和许可记录,见 [legal/licenses](./legal/licenses.md)。
- 描述一款游戏时说它的类型和规则,不说它「像哪一款游戏」。

这条原则记录在 [ADR-016](./decisions.md),贡献流程里的对应要求见根目录的 [CONTRIBUTING](../CONTRIBUTING.md)。

## 计划中的类型

计划加入更多经典类型的原创游戏,目前没有日期:

- 基地防御坦克
- 横版平台跳跃
- 合作平台跳跃
- 迷宫炸弹
- 合作清版街机
- 跑动射击

每一款都会使用原创的名称、角色、美术和关卡。进度见 [07-roadmap](./07-roadmap.md)。

## 决策变更(2026-11-11)

本文此前描述的是另一个产品:竖屏手机上的 UGC 应用,范式是「Fork 一个游戏 → 用自然语言让 AI 修改 → 发布到社区」,分为 Runtime、Mod DSL、AI Layer、Community 四层,并以用户数、Mod 数、Fork 数以及 Fork 转化率、AI 改完发布率、二级 Fork 深度作为成功指标。

2026-11-11 项目所有者决定把产品改为本文现在描述的主机风格启动器,理由与后果见 [ADR-016](./decisions.md)。旧结论里仍然有效的部分:

- Runtime 与 Mod DSL 两层原样保留,现在是每款游戏的实现方式。
- 「AI 只产出 DSL,不生成可执行代码」(ADR-004)仍是在线服务的约束。
- AI Layer 与 Community 两层的服务端实现保留在可选的在线服务里;客户端里对应的界面已经移除。

旧的成功指标针对的是 Fork 与 Mod 的数量,不再适用于现在的产品;新的衡量方式尚未确定。
