# 开发计划

## 原则

1. **先验证最贵的不确定性,再写业务。** 最贵的两个不确定性是:技术栈选型对不对(全 Godot 的 IME/列表能不能忍)、核心假设成不成立(AI 改 DSL 有没有创造感)。
2. **MVP 砍到只验核心闭环。** 那个精美社区壳(签到/商城/私聊/青少年模式)对验证「AI Mod 创作成立吗」毫无帮助,属于后续阶段。
3. **守住 GameSession 边界。** 从第一行代码起,Shell 和 Runtime 解耦,保住逃生口。

## Phase 0 — 技术 Spike(1~2 周)⭐ 最先做

**目标**:用最小代价买两个确定性——全 Godot 选型是否成立、5 端导出闭环是否通。
**不写任何业务逻辑。** spike 红了只亏两周,而不是三个月后推倒重来。

清单:

- [x] **第 0 项 · DSL Schema 地基**:Shooter、Survivor、Tower Defense 均已有版本化 schema/baseline；RFC 6902、迁移与双端黄金测试已落地。
- [ ] **中文 IME 实测**:一个中文输入框 + 一个评论/私聊列表,**真机 + 移动端 + 长文本私聊场景**上手打中文,做到能下确定性结论。← 决定全 Godot 生死(注意:推翻代价不是「只换游戏侧」,而是整个 Shell 重写,见下「决策门」)
- [ ] **虚拟化列表原型**:500+ 条的回收式滚动列表,验**基础滚动性能**(不定高/楼中楼/下拉刷新是后续长期摩擦,此处只证地基)。
- [x] **最简游戏 + GameSession 边界**:`GameSession`、三 Runtime 与真实 `PlayView` 均已接通并由 headless 测试覆盖。
- [x] **RuntimeLoader 雏形**:版本校验、同 major 兼容、迁移、三 Runtime 注册与内容映射均已实现。
- [ ] **5 端导出**:同一工程导出 iOS / Android / macOS / Windows,真机各装一遍跑通。
- [x] **AI → DSL 打通(直连一家)**:ClaudeProvider、强制结构化 patch、apply、schema 校验、重试与审计均已实现；真实调用仍需供应商 key。
- [ ] **产品验证 · 创造感盲测**:用预埋枚举让几个目标用户各改出多版,盲测评估「换皮感 vs 创造感」——这是文档自己定义的**最贵不确定性**,不能只验技术连通。
- [ ] **裸 PGC 留存**:官方 Shooter 基线游戏**不靠 Mod**,自身能不能留住人(冷启动的飞轮根节点)。

**退出标准**:IME 与列表手感可接受 + 5 端都能跑 + 「自然语言 → DSL → 游戏里看到变化」端到端通一次 + **盲测能感知到「我的版本」而非换皮** + **裸 PGC 有基本留存信号**。
**注意**:前 6 项验的是「技术管道通不通」;后 2 项验的是「产品该不该做」。只过技术项 = 花钱验证了一个便宜命题,核心假设仍未证。
**决策门**:达标 → 进 Phase 1 全量;IME 不达标且为核心场景 → 触发 [04-architecture](./04-architecture.md) 的推翻条件,改 Flutter+嵌入方案——**代价是 [16-client-architecture](./16-client-architecture.md) 整个 Shell(设计系统/列表/导航/所有 screens)用 Flutter 重写,不是「只换游戏侧」**,所以 IME 这一项必须验到能下确定结论。

## Phase 1 — 验证 AI Mod 创作(4~6 周)

**目标(来自原始 MVP)**:验证「AI Mod 创作是否成立」。指标:100 用户 / 1000 Mod / 500 Fork。

**做**:

- 用户系统(手机号验证码登录 + 一种第三方;实名占位)
- **Shooter Runtime**:一个打磨过的、好玩的官方基线游戏 + 一批预埋武器/敌人/Boss/掉落(这批「内容清单」是本阶段真正的工作量,见 [05-dsl-design](./05-dsl-design.md))
- **DSL 编辑器**:AI 自然语言输入 + 灵感 chips + 实时预览(改完即时在 Runtime 里看到)
- **AI 修改**:后端 `ai` 模块,直连一家模型,schema 约束 + 校验 + 评测集
- **发布**:把生效 DSL 存为 Mod,进审核
- **Fork**:从任意 Mod 一键 Fork(补丁链),展示创作链
- 最小社区:列表 + 详情 + Fork,够支撑「玩→改→发布→被 Fork」闭环即可
- 埋点:Fork 转化率、AI 改完发布率、二级 Fork 深度(见 [01-vision](./01-vision.md))

**不做**:联机、广告、商城、私聊、签到/任务、多 Runtime、复杂社交。

**周期**:4~6 周。

## Phase 2 — 丰富与留存(2~3 月)

- **Survivor Runtime**、**Tower Defense Runtime**(各自的 DSL schema + 内容清单)
- 评论系统、热门榜(热门/飙升/新作)
- 社交补全:关注、私聊、消息
- 原生集成按需补:分享、推送
- 合规补全:青少年模式、内容审核流程成形
- 指标目标:1000 用户 / 10000 Mod / 5000 Fork

## Phase 3 — AI 深化与联机(6~12 月)

- [x] 联机 Runtime:房间码/准备/开局、权威输入 tick、持久化玩家快照、确定性命中/结算、断线后快照恢复与 Godot 双账号集成已落地。
- [x] AI 自动平衡:三 Runtime 多参数联动调节、前后压力指标、Schema 复验与编辑器撤销/发布链已落地。
- [x] AI 自动生成关卡 / 敌人波次:提示词种子生成稳定 map 节点，支持连续扩展不覆盖，三 Runtime 与双端集成已验证。
- 创作者生态:作品管理、收益/数据中心、商城
- [x] 桌面端体验深化:Godot NativeMenu（支持平台）、编辑器 fallback、真实 Runtime 多窗口预览及 `.forgeplay.json` 导入/导出已接通。

## 里程碑速查

| 阶段 | 周期 | 出口标志 |
|---|---|---|
| Phase 0 Spike | 1~2 周 | 全 Godot 选型证实 + 5 端导出 + 端到端 DSL 闭环通一次 |
| Phase 1 MVP | 4~6 周 | 「玩→AI改→发布→Fork」成立,核心指标达标 |
| Phase 2 | 2~3 月 | 三 Runtime + 社交 + 留存,指标上一量级 |
| Phase 3 | 6~12 月 | 联机 + AI 生成结构 + 创作者经济 |

## 当前最近一步

仓库内 Phase 3 代码清单（联机、AI 平衡、结构生成、创作者经济、桌面深化）均已形成自动化闭环。剩余决策门是无法由仓库/headless 伪造的真机 IME/滚动/五端安装、供应商与监管环境，以及目标用户盲测和留存。
