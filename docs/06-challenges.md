# 难点与风险

按「能否掀翻项目」排序。每项标注:严重度、是一次性投入还是长期摩擦、缓解策略。

## A. 产品级:DSL 表达力天花板 —— 最高,长期

- **风险**:DSL 太死则用户无创造感(换皮工具),太活则 AI 接不住。这是产品成败核心,不是工程问题。
- **缓解**:把它当作持续调优的产品工作而非一次性设计;Phase 1 先窄(Shooter,少而精的预埋)验证「AI 改 DSL 能不能让人有创造感」;盯 [01-vision](./01-vision.md) 的「AI 改完发布率」「Fork 转化率」做反馈。
- 详见 [05-dsl-design](./05-dsl-design.md)。

## B. 产品级:Runtime 版本治理 —— 高,长期

- **风险**:Runtime 升级使存量 Mod 集体失效。
- **缓解**:DSL pin 版本 + 语义化版本 + major 必带迁移 + `RuntimeLoader` 加载前校验。Phase 1 就立规矩。详见 [05-dsl-design](./05-dsl-design.md) §Runtime 版本治理。

## C. 技术级:中文/日文 IME 输入 —— 高,长期摩擦(全 Godot 的命门)

- **风险**:Godot 4.x 的 IME 仍弱于原生,移动端软键盘 + 候选词联动别扭。你的 App 到处是输入(AI prompt、评论、私聊、搜索)。
- **这是唯一能推翻「全 Godot」决策的变量。**
- **缓解**:
  - **spike 第一优先级实测**(见 [07-roadmap](./07-roadmap.md)):真机上手打中文,评估可接受度。
  - 设计上减少重输入场景的依赖:AI prompt 可提供大量预设 chips(原型已有),降低纯打字比例。
  - 若实测不可接受且私聊/评论是核心 → 触发决策推翻,退回 Flutter+嵌入。
- **注意**:CJK **显示**没问题(HarfBuzz),疼的只是**输入**。

## D. 技术级:长列表虚拟化 —— 高,一次性投入

- **风险**:`ScrollContainer` 默认不回收节点,长 feed/榜单/评论全实例化 → 内存性能爆。
- **缓解**:自研虚拟化列表组件(只渲染可见项 + 节点池复用)。spike 阶段就要做出原型验证手感和性能。写好一次,全 App 复用。

## E. 技术级:原生系统集成 × 4 端 —— 高,一次性但量大

- **风险**:推送、内购/支付(App Store/Google Play/微信/支付宝)、分享、深链、第三方登录,Godot 无内置,逐平台写 GDExtension 插件,iOS/Android/mac/Win 各一份。
- **缓解**:
  - 抽象统一接口,平台分实现,Shell 只调接口。
  - 按需排期:Phase 1 几乎不需要支付/推送,可推迟;登录在 Phase 1 需要但可先做手机号验证码 + 一种第三方。
  - 认清这是任何方案都要付的成本(Flutter 也要装支付插件,只是有成熟现成包)。

## F. 技术级:AI 输出可靠性 —— 高,可工程化

- **风险**:模型产出非法 JSON / 不符合 schema / 改错位置 / 不平衡。
- **缓解**:
  - structured output / function calling 强制 schema。
  - 后端 JSON Schema 二次校验,失败重试(有限次)+ 兜底(返回明确错误而非脏数据)。
  - 早期建一个 prompt 评测集(几十条真实意图),量化「合法率」「意图命中率」,作为换模型/调 prompt 的回归基准。
  - 精确定位修改:大 DSL 用 JSON Patch 路径而非整份重写,降 token 成本与改错率(待 spike 验证,见 [05-dsl-design](./05-dsl-design.md))。

## G. 工程级:无障碍 —— 中,长期

- **风险**:Godot 4.5 才完整集成 AccessKit(4.4 起早期铺垫),当前覆盖不全、落后原生;上架质量/合规会被盯。
- **缓解**:用 Godot 新的无障碍能力,关键路径(登录、核心导航)优先;接受非核心界面初期不完美。

## H. 工程级:桌面原生约定(mac/win)—— 中,一次性

- **风险**:原生菜单栏、窗口 chrome、文件对话框、多窗口需自补。
- **缓解**:封装为平台插件层的一部分;桌面端整体痛感低于移动端,可后置。

## I. 业务级:合规 —— 高,硬约束

- **风险**:国内 UGC + 游戏 + AI 生成内容,涉及版号、实名、青少年模式、内容审核(AI 生成 + 用户 Fork 双重)。
- **缓解**:架构预留 `moderation` 模块;实名/青少年模式原型已有;AI 生成内容走审核队列;**这是不可裁剪项,排期里当一等需求**。

## J. 业务级:冷启动 —— 高

- **风险**:UGC 平台鸡生蛋,没内容没人来。
- **缓解**:官方 Runtime 自带的几款游戏要足够好玩,先以 PGC 撑消费侧;运营上引导「玩 → 改一版」的最短转化。

## K. 成本级:AI token 成本 —— 中,长期

- **风险**:每次创作调大模型,易被滥用、成本不可控。
- **缓解**:后端统一调用 + 限流 + 用户配额(免费额度 + 付费/看广告补充);按成本路由模型(简单改动用便宜模型);精确定位修改省 token。
