`github.com/yldm-tech/classic-games/packages/sdk` 是 Classic Games 后端 HTTP API 的类型化 Go 客户端，源码在 <a href={repoDir('packages/sdk')}>packages/sdk</a>。它只依赖标准库，`classic-games` CLI 和 `classic-games-mcp` 服务都用它访问后端。

:::note[可选的在线服务]
后端以及构建在它之上的工具都是可选组件。经典厅的启动器不发网络请求，也不使用后端、CLI、MCP 服务或 SDK；不运行它们也能玩全部游戏。
:::

:::note
完整的方法列表和类型说明以 <a href={repoFile('packages/sdk/README.md')}>packages/sdk/README.md</a> 和源码里的文档注释为准。
:::

## 引入

`github.com/yldm-tech/classic-games/packages/sdk` 是仓库内的模块名，没有发布到模块代理。仓库里的其他模块通过 `replace` 指向它：

```
require github.com/yldm-tech/classic-games/packages/sdk v0.0.0

replace github.com/yldm-tech/classic-games/packages/sdk => ../../packages/sdk
```

相对路径按你的模块所在位置调整。

## 示例

下面的程序用访客身份登录，取出 Shooter 的基线 DSL，让后端的 AI 生成一段补丁，再把补丁存成草稿 Mod。它对本地用 `make dev` 启动的后端可以直接运行：

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/yldm-tech/classic-games/packages/sdk"
)

func main() {
	ctx := context.Background()

	client, err := sdk.New(sdk.DefaultBaseURL)
	if err != nil {
		log.Fatal(err)
	}

	session, err := client.LoginGuest(ctx)
	if err != nil {
		log.Fatal(err)
	}
	client.SetToken(session.Token)

	baseline, err := client.GetRuntimeBaseline(ctx, "shooter", "1.0.0")
	if err != nil {
		log.Fatal(err)
	}

	result, err := client.GenerateMod(ctx, sdk.GenerateModRequest{
		Runtime:    "shooter@1.0.0",
		CurrentDSL: baseline,
		Prompt:     "把飞机换成猫",
	})
	if sdk.IsCode(err, sdk.CodeQuotaExceeded) {
		log.Fatal("daily AI quota used up")
	}
	if err != nil {
		log.Fatal(err)
	}

	draft, err := client.CreateMod(ctx, sdk.CreateModRequest{
		Runtime:      "shooter@1.0.0",
		Patch:        result.DSLPatch,
		AIProvenance: result.Provenance,
		Draft:        true,
	})
	if err != nil {
		log.Fatal(err)
	}
	fmt.Printf("%d patch operations, %d retries, saved as draft %s\n", len(result.DSLPatch), result.Retries, draft.ID)
}
```

## 要点

- `sdk.New` 接收的是后端根地址，例如 `http://localhost:8080`。`/api/v1` 前缀由客户端自己加。
- 登录方法只返回会话，不会改动客户端。要使用这个会话，调用 `SetToken`。
- 列表接口用游标分页，返回 `Page[T]`。`sdk.Paginate` 可以把所有页串成一个迭代器。
- 非 2xx 的响应一律返回 `*sdk.APIError`，里面有 HTTP 状态码和后端的错误码。可以用 `errors.As` 取出，也可以用 `sdk.IsCode`、`sdk.IsStatus`、`sdk.IsNotFound` 判断。
- 有两类错误由客户端自己给出，用 `errors.Is` 判断：`sdk.ErrInvalidArgument` 表示 id 为空、含 `/`、或是 `.` / `..`，这时不会发出请求；`sdk.ErrBadResponse` 表示 2xx 响应不是预期的 JSON 或超过 32 MiB。把 `mine` 这类本身是后端路由的词当作 id 传给 `GetGame` 等单资源读取方法，得到的是 `404 NOT_FOUND`，不会返回一个空对象。
- `GenerateMod` 返回的 `NewDSL` 已经由后端按 Schema 校验过。它不会保存任何东西，要保存结果需要像上面那样调用 `CreateMod`，或用 `SaveDraft` 存到已有草稿上；把返回的 `Provenance` 一并传回去，Mod 才会被标记为 AI 生成；后端只有设置了 `CLASSIC_GAMES_SECRET` 才会签发它。
- 发布（`PublishDraft`）后的游戏状态是 `reviewing`，审核通过后才公开。
- 开发环境后端预置的展示游戏背后没有 mod，对它们调用 `GetGameDSL` 或 `ForkGame` 会得到 404（错误码 `GAME_HAS_NO_MOD`）；示例因此从 Runtime 基线开始。
- 需要离线应用补丁或按 Schema 校验时，用 `github.com/yldm-tech/classic-games/packages/dsl`（`packages/dsl`）。SDK 的 `PatchOp` 与 `dsl.Op` 字段相同，可以逐元素转换。

接口本身的契约见 [API 设计](/docs/09-api-design/)。
