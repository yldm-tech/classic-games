Classic Games（经典厅）是一个主机风格的游戏启动器，自带一组原创游戏。项目处于预发布阶段：没有公开构建，也没有商店版本。下面的步骤全部从源码开始，用到的 `make` 目标都定义在仓库根目录的 <a href={repoFile('Makefile')}>Makefile</a> 里。

## 前置条件

| 工具 | 版本 | 用途 |
|---|---|---|
| Godot | 精确的 4.6.3 | 启动器与游戏。用标准版，不要用 .NET 版。版本锁在 `apps/client/.godot-version`，测试脚本会检查 |
| GNU Make | 任意较新版本 | 统一入口 |
| Go | 1.26 | 只有可选的在线服务需要：后端、CLI、MCP 服务与 SDK。各模块的 `go.mod` 声明 `go 1.26`，较新的 Go 工具链会按需下载对应版本 |
| Node.js 与 pnpm | Node 22.23.4 以上，pnpm 12 | 只有构建本站时需要 |

## 运行启动器

先让 Godot 导入工程资源，只需要做一次：

```bash
make import GODOT=/path/to/godot
```

再启动工程，它的主场景就是启动器：

```bash
/path/to/godot --path apps/client
```

也可以用 Godot 4.6.3 编辑器打开 `apps/client` 后运行。

启动器用手柄或键盘操作：方向键或十字键移动焦点，Enter 或 A 确认，Esc 或 B 返回，F11 在主机模式和 PC 模式之间切换。全部进度保存在一个本地存档文件里。启动器不发网络请求，所以不需要先启动别的东西。

## 可选的在线服务

仓库里还有一个 Go 后端、一个命令行工具、一个 MCP 服务和一个 Go SDK。它们实现了 Mod DSL 的校验与补丁，以及一套在线服务的 API（账号、目录、Mod、社区、商业化）。它们可以运行、有测试，但启动器没有接入：如果只想玩游戏，或者只改启动器和游戏，可以跳过这一节。

### 启动后端

```bash
make dev
```

后端默认监听 `:8080`，改端口用 `PORT=9090 make dev`。默认数据库是工作目录下的一个 SQLite 文件，不需要另外安装数据库。

没有设置 `ANTHROPIC_API_KEY` 时，后端用确定性的本地 provider 代替模型，所以不需要任何密钥就能启动；设置后调用真实模型。全部环境变量见仓库根目录的 <a href={repoFile('.env.example')}>.env.example</a>。

确认后端已经启动：

```bash
curl http://localhost:8080/healthz
```

接口文档在 `http://localhost:8080/swagger/index.html`。

### 构建 CLI 与 MCP 服务

```bash
make cli-build    # apps/cli/bin/classic-games
make mcp-build    # apps/mcp/bin/classic-games-mcp
```

CLI 的 DSL 命令可以离线使用，其余命令需要后端：

```bash
export PATH="$PWD/apps/cli/bin:$PATH"
classic-games dsl validate apps/client/runtime/shooter/baseline.dsl.json   # 离线
classic-games server health                                                # 需要后端
classic-games auth login
classic-games mods list
```

接下来见 [CLI](/developers/cli/) 和 [MCP 服务](/developers/mcp/)。

## 测试与门禁

| 命令 | 作用 |
|---|---|
| `make launcher-test GODOT=/path/to/godot` | 启动器的无头测试：存档、目录、首页焦点、开局与结算 |
| `make settings-test`、`make library-test`、`make pc-mode-test`、`make game-flow-test` | 设置屏、游戏库与成就、PC 模式，以及游戏菜单、HUD、暂停、结算流程的无头测试。都需要带 `GODOT=/path/to/godot` |
| `make launch-test GODOT=/path/to/godot` | 启动主场景，检查启动器装配完成 |
| `make boundary-test` | 客户端依赖方向检查，以及检查器自身的测试 |
| `make architecture-test` | 仓库级架构边界检查 |
| `make test` | 后端 `go test` |
| `make vet` | 全部 Go 模块的 `go vet` |
| `make dsl-test`、`make sdk-test` | 共享 Go 包的测试 |
| `make cli-test`、`make mcp-test` | CLI 与 MCP 服务的测试 |
| `make go-standalone` | 每个 Go 模块在 `GOWORK=off` 下 `go vet` 与 `go test` |
| `make ci GODOT=/path/to/godot` | 依次运行 Go 与 Godot 的全部门禁 |
| `make ci-web` | 安装依赖、类型检查并构建本站 |

`make help` 列出全部目标。

## 构建本站

本站是仓库里的 `apps/web`，用 Astro 和 Starlight 构建。在仓库根目录执行：

```bash
pnpm install
pnpm web:dev      # 本地开发
pnpm web:check    # 类型检查
pnpm web:build    # 输出静态文件到 apps/web/dist
```
