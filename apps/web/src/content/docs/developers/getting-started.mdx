Classic Games 处于预发布阶段：没有公开构建，也没有应用商店版本。下面的步骤全部从源码开始，用到的 `make` 目标都定义在仓库根目录的 <a href={repoFile('Makefile')}>Makefile</a> 里。

## 准备

| 工具 | 版本 | 用途 |
|---|---|---|
| Go | 1.26 | 后端、CLI、MCP 服务和 SDK。各模块的 `go.mod` 声明 `go 1.26`，较新的 Go 工具链会按它自动下载对应版本 |
| Godot | 4.6.3，必须精确 | 客户端。版本锁在 `apps/client/.godot-version`，测试脚本会检查 |
| GNU Make | 任意近期版本 | 统一入口 |
| Node.js 与 pnpm | Node 22.23.4 以上，pnpm 12 | 只在构建本站时需要 |

## 获取源码

<Code code={`git clone ${REPO_URL}.git\ncd classic-games`} lang="bash" />

## 启动后端

```bash
make dev
```

后端默认监听 `:8080`，换端口用 `PORT=9090 make dev`。数据库默认是工作目录下的 SQLite 文件，不需要额外安装数据库。

没有设置 `ANTHROPIC_API_KEY` 时，后端使用确定性的本地 provider，所以不需要任何密钥就能走通「自然语言 → 补丁 → 校验」这条链路。设置后改用真实模型。全部环境变量见仓库根目录的 <a href={repoFile('.env.example')}>.env.example</a>。

确认后端已经起来：

```bash
curl http://localhost:8080/healthz
```

接口文档在 `http://localhost:8080/swagger/index.html`。

## 运行客户端

先让 Godot 导入资源：

```bash
make import GODOT=/path/to/godot
```

再启动工程。客户端从环境变量 `CLASSIC_GAMES_API` 读取后端地址：

```bash
CLASSIC_GAMES_API=http://127.0.0.1:8080 /path/to/godot --path apps/client
```

也可以用 Godot 4.6.3 编辑器直接打开 `apps/client`。

## 构建 CLI 与 MCP 服务

```bash
make cli-build    # apps/cli/bin/classic-games
make mcp-build    # apps/mcp/bin/classic-games-mcp
```

后端启动后，第一次使用大致是这样：

```bash
export PATH="$PWD/apps/cli/bin:$PATH"
classic-games server health
classic-games auth login
classic-games ai generate "turn the player into a cat" --runtime shooter@1.0.0 --save
classic-games mods list
```

后续内容见 [CLI](/developers/cli/) 和 [MCP 服务](/developers/mcp/)。

## 测试与门禁

| 命令 | 作用 |
|---|---|
| `make test` | 后端 `go test` |
| `make vet` | 全部 Go 模块的 `go vet` |
| `make dsl-test`、`make sdk-test` | 共享 Go 包的测试 |
| `make cli-test`、`make mcp-test` | CLI 与 MCP 服务的测试 |
| `make go-standalone` | 每个 Go 模块在 `GOWORK=off` 下的 `go vet` 与 `go test` |
| `make boundary-test` | 客户端依赖方向检查，以及检查器自身的测试 |
| `make architecture-test` | 仓库级架构边界检查 |
| `make spike GODOT=/path/to/godot` | Godot headless 的 Runtime 与 DSL 测试 |
| `make ui-test GODOT=/path/to/godot` | Shell UI 断言 |
| `make ci GODOT=/path/to/godot` | 依次运行 Go 与 Godot 的全部门禁 |
| `make ci-web` | 安装依赖、类型检查并构建本站 |

`make help` 会列出所有目标。真实的双端集成测试是单独一个脚本，它会在 8099 端口启动后端，再让 Godot 客户端调用真实接口：

```bash
GODOT=/path/to/godot scripts/spike-integration.sh
```

## 构建本站

本站是仓库里的 `apps/web`，用 Astro 和 Starlight 构建。在仓库根目录执行：

```bash
pnpm install
pnpm web:dev      # 本地开发
pnpm web:check    # 类型检查
pnpm web:build    # 输出静态文件到 apps/web/dist
```
